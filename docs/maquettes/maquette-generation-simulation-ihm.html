Ce que je vais coder dans XPGAnalyser

La fenêtre ci-dessus est une maquette qui calcule vraiment : empreintes, graphe de dépendances, contrôle des scripts avec ligne et colonne, exécution des scripts, cache, deux rémanences. Seul le rythme d'affichage est ralenti (réglage « Rythme »), pour qu'on suive chaque tâche. Dans le logiciel, la barre suit le travail réel et rien n'attend. Voici comment ce sera codé dans l'application, en partant de ce qui existe.

Les services

Dans src/hmi/build/, sans écran (testables seuls), et dans src/app/hmi/ pour ce qui s'affiche. Le travail long tourne hors du fil de l'interface, sur une copie du projet. Il publie sa progression, s'annule entre deux tâches, et ne remplace jamais un artefact valide par un fichier incomplet.

Les formats

Comme les fichiers IHM : du texte, une ligne par enregistrement (un mot, puis des clé=valeur), une dernière ligne fin pour refuser un fichier coupé, écrit à côté (.tmp) puis renommé, l'ancien gardé en .bak.

Cache de build · Projet\.xpg\build\build-cache.txt

xpg-build-cache version=1 generateur=1.12.0 projet="Armoire_Gaz" ecrit=2026-10-08T10:42:09
element id=i20 type=script-vue chemin="IHM/Vues/Vue_Vannes/OnCycle"
  contenu=9c1e2f3a config=4be0c711 dependances=77a01f2c interface=0e33d5a8
  valide=2026-10-08T10:42:09 generateur=1.12.0
  generation=Généré compilation=Compilé
  artefact="build/ihm/vues/Vue_Vannes/OnCycle.st" empreinte_artefact=1d93be04
dependance de=i20 vers=a02 mode=interface empreinte=5c2a90e1 signature="Pression_Gaz : REAL"
diagnostic de=i29 gravite=Avertissement code=W304 ligne=1 colonne=33
  etape=Compilation message="{Consigne:0.0} : inconnu" suggestion="{Consigne_Pression}"
fin

Rémanence de simulation · Projet\.xpg\simulation\remanence-simulation.txt

xpg-remanence-simulation version=1 projet="Armoire_Gaz"
  session=3 ecrit=2026-10-08T10:51:30 cycle=412 vue=Vue_Vannes
valeur id=i01 nom=Compteur_Purges type=INT valeur=3
valeur id=i02 nom=Consigne_Pression type=REAL valeur=6.5
valeur id=a03 nom=Niveau_Cuve type=REAL valeur=48.25 origine=api-simulee
instance cle="Vue_Vannes.Vanne_3" Pos=100
fin

Restaurée par id, jamais par l'ordre. Le nom ne sert qu'au journal.

Variables rémanentes du poste · %ProgramData%\XPGAnalyser\Exploitation\<projet>\remanence-exploitation.txt

xpg-remanence-exploitation version=1 poste="POSTE-ARMOIRE-01"
  ecrit=2026-10-08T07:12:44
valeur id=i02 nom=Consigne_Pression type=REAL valeur=6.2
  date=2026-10-08T07:12:44 controle=1f3a9b2c
fin

Chaque valeur a son empreinte de contrôle. Ce fichier n'est jamais écrit par la simulation de développement, ni effacé par Générer ou Compiler.

Les règles d'invalidation

Ce qui changeCe qui est à refaire
Le corps d'un script ou d'une fonctionLui seul (compilation). Ses appelants restent à jour : son interface n'a pas changé.
La signature d'une fonction (paramètres, retour) ou son nomElle, et ses appelants (obsolètes, à recompiler). Un renommage met à jour les appels, qui deviennent « Modifié ».
Le type ou le nom d'une variable (IHM ou API)Elle, et ce qui la lit ou l'écrit : scripts, animations, alarmes, historiques, recettes, tables d'échange.
Le dessin d'un symboleLe symbole, et les vues qui en posent une instance (dépendance de contenu : l'instance est déballée).
Les paramètres d'un symbole ou d'une popupLui, ses instances et ses appelants.
Un réglage visuel d'une vue (titre, fond)Cette vue seule (génération, sans compilation).
Un commentaire, une description, l'ordre des variables, ce qui ne sert qu'à l'éditeurRien, et la simulation continue.
Un ajout / une suppressionL'élément ajouté / l'artefact supprimé est retiré, et ce qui l'utilisait passe en « Dépendance invalide ».
Un déplacement ou un renommage de dossierLes éléments déplacés (chemin), pas leurs utilisateurs : l'identifiant est stable.
Une nouvelle version du générateurTout ce qu'a produit l'ancienne (obsolète, horloge).
Un artefact absent ou altéré (empreinte)Cet élément.
Un cache absent, illisible ou d'une autre versionTout, avec la raison dans Sorties, puis un cache propre.
Un élément en échecCe qui en dépend n'est pas généré (« Dépendance invalide »). Le reste continue, et la simulation ne démarre pas tant qu'il y a une erreur bloquante.

Les tests (les 28 du cahier)

Dans tests/hmi_build_test.cpp (nouveau, sans écran) et hmi_editor_test (l'interface) :

  • Build : démarrage sans modification (aucune tâche) ; première génération complète ; un seul script ; une variable API utilisée par plusieurs vues ; une vue sans impact sur les autres ; renommage d'une fonction IHM ; suppression d'un symbole utilisé ; échec de compilation ; correction après échec ; régénération d'un élément, d'une branche, de tout ; cache absent ; cache corrompu ; artefact supprimé à la main.
  • Simulation : arrêt après modification ; sauvegarde de la rémanence de simulation ; restauration ; Redémarrer avec effacement ; génération sans effacement ; option désactivée.
  • Exploitation : variable rémanente ; variable non rémanente ; changement de type compatible ; changement incompatible ; coupure pendant une sauvegarde.
  • IHM_LOG : appel valide ; appel invalide (niveau inconnu, ordre, type du message, nombre d'arguments) ; navigation vers la source depuis un diagnostic.

Lot 1 : le moteur de buildServices, cache, artefacts, 13 états et icônes, Générer / Régénérer / Compiler partout (barres d'outils, menus, éditeurs), panneau de progression, « Projet à jour ».

Lot 3 : la simulationDémarrer / Arrêter / Redémarrer / Générer et redémarrer, simulation sur le projet généré, arrêt sur modification, rémanence de simulation.

Chaque lot arrive avec son installateur, ses captures et sa notice, comme d'habitude. Une remarque sur la maquette change le lot suivant, sans attendre la fin.

Ce qui restera limité

  • Les scripts C et C++ restent relus, jamais exécutés : ils gardent l'icône « non compilable ».
  • Les sections de l'automate ne se compilent pas ici. L'étape API génère ce que l'IHM en voit, et le simulateur de l'automate garde sa propre préparation.
  • Deux instances sur un même projet : le verrou empêche deux builds en même temps, et la seconde le dit.
  • Tout sera vérifié sous Wine. Le lancement sur un vrai Windows reste à faire de votre côté.
