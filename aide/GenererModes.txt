#! summary = Genere la section qui fait tourner les modes de marche : l'appel du gestionnaire, puis le CASE des sous-routines.
#! usage = La section se lit en deux moities, et la separation est le coeur de l'affaire. DFB_MODE_MANAGER decide QUEL mode est actif : c'est de la donnee - une condition, une priorite, un temps minimum - et ca vit dans un DDT.
#! usage = CETTE SECTION decide CE QUI TOURNE dans chaque mode : c'est une suite de noms de sous-routines dans un ORDRE, et une suite ordonnee de noms ne se range pas dans un DDT. C'est du code, et il faut donc l'ecrire.
#! usage = RELANCEE, ELLE REECRIT LA SECTION ENTIERE plutot que d'y ajouter. Une section de modes a moitie ancienne et a moitie nouvelle est pire que les deux. Ce qui a ete ajoute a la main dans cette section sera perdu.
#! usage = LES QUESTIONS PAR MODE N'APPARAISSENT PAS DANS CETTE LISTE. Leurs cles sont calculees dans une boucle (m0nom, m0sr, m1nom...), donc l'aide ne peut pas les nommer d'avance. Pour chaque mode, la macro demande son nom et la liste de ses sous-routines separees par des virgules, dans l'ordre d'appel.
#! usage = Les conditions d'entree dans un mode se calculent AILLEURS et arrivent ici par <table>[i].Req.
#! usage = Une macro se relance. C'est la regle de toutes celles-ci : relancee sur un projet ou elle a deja tourne, elle ne doit rien casser et rien dupliquer. C'est pour ca qu'elles testent avant de creer, et qu'elles disent "existe deja" au lieu de s'arreter.
#! usage = Les questions arrivent par TOURS. Ask() enregistre une question, AskNow() les pose. Une macro coupe ses tours la ou une reponse decide des questions suivantes : demander les quatre noms de section quand on vient de repondre "une seule famille" remplirait l'ecran de champs qu'on laisserait vides.
#! example = GestionModes(Count := 4, CycleMs := 20, Def := Modes, ...);

#! example =     0:  Init_Systeme;
#! example =         Acquisition;
#! example =     1:  Acquisition;
#! example =         Production;
#! example = END_CASE;
#! see = CreerSR, AppelerSR, EnsureSection
#! param section = La section generee. Elle est ECRASEE a chaque execution : n'y ecrivez rien a la main.
#! param table = Le tableau ARRAY[0..15] OF ST_MODE_Def qui porte la definition des modes. Cree s'il n'existe pas. C'est la que se posent les conditions d'entree, les priorites et les temps minimum.
#! param instance = Le nom de l'instance de DFB_MODE_MANAGER. Creee si elle n'existe pas.
#! param courant = La variable INT qui porte le mode actif. La macro cree aussi <courant>_Prec et <courant>_Ms, que le gestionnaire remplit : le mode precedent, et depuis combien de temps on est dans celui-ci.
#! param combien = Le nombre de modes, de 1 a 16. C'est aussi le nombre de tours de questions qui suivent : un par mode.
#! param cycle = La periode de la tache en ms, telle qu'elle est reglee dans la configuration. Elle sert au gestionnaire a compter les temps. Une valeur fausse ici fausse tous les temporisateurs de modes.
